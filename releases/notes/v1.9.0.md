# v1.9.0

**新增 SMART 式的設備健康資訊。** 設備現在會長期記錄累計通電時數、開機與重置次數、OTA 歷史和晶片溫度，重開機和斷電後都會保留。

## 查詢方式

- 新指令 `health`。這個指令不需要維護模式，Direct（ESP-NOW）模式也能用。回應不到 1 KB。
- 終端機可以 `cat /proc/health`，看到的是純文字版本。
- `capabilities` 的 `subsystems` 多了 `health: true`。
- `status` 不變：健康資訊不放進 `status`，Direct 模式 compact status 的大小不受影響。

## 記錄的項目

| 群組 | 欄位 |
|---|---|
| 總評 | `health.verdict`：`ok` / `warn` / `fail`；`health.reasons` 說明原因 |
| 時間 | 累計通電 `power_on_s`，拆成運行中 `awake_s` 和軟關機 `soft_off_s`；感測器掃描時數 `scan_s`；本次開機 `session_s`；最長連續運行 `longest_session_s`；首次時間同步 `first_seen_unix` |
| 開機 | 開機次數 `boot_count`；各重置原因的次數 `reset_counts`；當機總數 `crash_total`；開始記錄時的開機序號 `tracked_since_boot` |
| 韌體 | 開始記錄時的版本 `first`；版本變更次數 `changes`，OTA 和序列埠燒錄都算；OTA 成功 `ota_success`；OTA 回滾 `ota_rollback` |
| 環境 | 晶片目前、最高、最低溫度；這版韌體的最低可用記憶體 `min_free_heap` |
| 連線 | Wi-Fi 斷線次數 `wifi_disconnects`。軟關機時暫停 Wi-Fi 不算斷線 |
| 輸入 | 按鍵次數 `button_presses`，只有 v1.0.F、v1.5.F 有這個欄位 |

總評的規則：

- `fail`：連續開機失敗，已經進入 safe maintenance。
- `warn`：有下列任一情況。
  - 最近 10 次開機內有 panic、看門狗或電壓不足重置。
  - 有 OTA 被回滾，而且之後還沒有新版本確認成功。
  - 晶片溫度 ≥ 80 °C。
  - 這版韌體的最低可用記憶體 < 16 KB。

## 儲存方式

- 使用獨立的 NVS namespace `nhos_life`，所有資料存成單一 blob。
- 寫入時機：開機時、每 10 分鐘一次、進入軟關機時，以及任何重開機之前。重開機前的寫入是透過 shutdown handler，所以 reboot 指令、OTA 套用、配對失敗改開設定入口等所有 `ESP.restart()` 都涵蓋。
- **直接拔電或當機，最多少算最後 10 分鐘。**
- 每天大約寫入 150 次，對 20 KB 的 NVS 磨損可以忽略。
- 計數**沒有任何指令可以清零**。

## 其他變更

- 重置原因多了 `usb`、`jtag`、`efuse`、`pwr_glitch`、`cpu_lockup` 的名稱。以前這些都顯示成 `unknown`。

## 相容性

- 計數從這一版開始記錄。舊設備的 `boot_count` 沿用原本的累計，其他數字從 0 開始。`tracked_since_boot` 會標出從第幾次開機開始記錄。
- 降版再升回來時：如果降到更舊的韌體後又升級，計數會接著原本的數字。如果讀到比本版新的格式，會重新開始記錄。
- Desktop v0.16.0 的診斷頁會顯示「設備健康」卡片。舊版 Desktop 可以用終端機的 `health` 查詢。

## 驗證

- 5 塊板子的 release build 均通過。
- `tests/` 靜態測試全部通過；新增 `tests_native/test_lifetime_policy.cpp`，測試累加、進位、溢位、millis 溢位和總評規則。
- **本版尚未經過實機驗證**。要確認的項目：
  1. `power_on_s` 會隨時間增加。
  2. 通電超過 10 分鐘後拔電再接回，時數有保留，`reset_counts.poweron` 加 1。
  3. OTA 一次之後 `ota_success` 加 1。
  4. Direct 模式下 `health` 能正常回應。
