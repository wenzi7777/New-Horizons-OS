# v1.23.0

**Devices pick a relay by quality, report the priority they are attached at, and no longer attach to the old NH Gateway.**

## Choosing a relay

- At boot, or when the current relay is gone (about 9 s without an answer), the device no longer takes the first answer: it collects every offer for 0.6 s and takes the best:
  1. priority: the relay that added this device or took it over last (its owner) first;
  2. a relay connected to the server first;
  3. lower latency first (within 30 ms counts as equal);
  4. fewer devices served first.
- Attached, nothing changes: a better relay appearing does not move the device; only its own relay refreshing or a requested move (a takeover) is taken.

## Reporting the current relay

- While attached (and not moving), FindMe carries the current relay and the priority it attached at. NH Studio, Pocket and headless use it to tell "taken over by another relay" from "another relay stood in while the owner was away"; in the second case the owner takes the device back when it returns.

## Old NH Gateway

- Version 1 offers, the old Python NH Gateway's, are ignored: a device never attaches to one again.

## Compatibility

- Needs NH Studio / Pocket / headless v2.5.0 or later and Desktop v1.9.0 or later: older ones send version 1 offers, which this firmware ignores. Update them first.
- Hub (ESP-NOW) mode is unaffected.
