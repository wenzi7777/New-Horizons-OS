# v0.17.0

## VD-CTL/R v1.5.F 2026.7

This is the first OTA release track for the v1.5.F hardware revision.  Its
dedicated 8 MB native-USB firmware and manifest are isolated from the v1.0.F
track, preventing cross-flashing between the two boards.

### Hardware support

- Adds the v1.5.F 14x14 matrix pin map, physical power-switch model, native
  ESP32-S3 USB recovery path, and RST/BOOT support.
- Adds MAX17048 voltage, state-of-charge, and rate reporting; BMM350 produces
  the same compensated `mag[3]` data contract as the existing magnetometer.
- Supports the two on-board WS2812B LEDs (system and battery) and nine
  external WS2812B LEDs on GPIO16.

### Battery behaviour

- Battery charging is manual by default and starts at the safe 100 mA limit.
- The Desktop **Detect battery ID** control can resample the POGO ID resistor.
  A detected 1k profile applies 100 mA and a 10k profile applies 200 mA.
- A missing or indeterminate ID remains manual; a saved manual profile is used
  when present, otherwise it stays at 100 mA.  The 100k provisionally-defined
  profile remains limited to 100 mA.

### Protocol and host compatibility

- v1.5.F sends protocol v5 with optional magnetometer and battery sections;
  v2-v4 receivers remain compatible.
- Battery status includes profile source, ID classification, charge limit,
  profile-resolution state, and thermal monitoring bypass state.

## Validation

- Native protocol/board regression suite and firmware Python suite passed.
- Clean Arduino builds passed for both v1.0.F and v1.5.F targets.
- Physical-device tests (power cutoff, USB recovery, sensors, battery ID and
  LEDs) still require the production board.
