# v1.12.0

**統一的時鐘服務：ESP-NOW 裝置終於有真實時間，WiFi 裝置優先向 Gateway 對時。壓力校正會說明每顆感測器被排除的原因、飽和時鎖在上限，並允許部分儲存。v2.2.C 改成 10×12。**

## 時鐘服務（取代 TimeSync）

所有需要真實時間的地方都改讀同一個 `ClockService`，時間來源依傳輸模式自動選擇。

- **ESP-NOW（Direct）模式**：向配對的 Hub 對時（需要 Hub v0.7.0）。
  - 以前這個模式其實完全拿不到時間：後端的自動推送只在 Gateway 路徑觸發，所以所有封包都是 `epochValid=false`。
  - 裝置主動送 12 B 的 TIME_REQ（`0xE8`），Hub 回 32 B 的 TIME_RESP（`0xE9`），用 NTP 的四時間戳算法扣掉來回延遲。
  - 每 15 秒一次；剛配對或手動同步時連送 4 次，取延遲最小的那次。
- **WiFi 模式**：優先向 Gateway 對時（需要 Gateway v0.6.0），Gateway 不回應才用 NTP。
  - 同一套封包走 UDP 13250。同一個 Gateway 底下的裝置共用一個參考時鐘，多台裝置一起收資料時對得比較齊。
  - Gateway 沉默滿 10 分鐘後，才改由 NTP 接手。
  - NTP 的重新校正間隔從 3 小時縮短為 10 分鐘（±20 ppm 的晶振 3 小時最多漂約 200 ms，10 分鐘約 12 ms）。
- **時間來源的優先順序**：Gateway > NTP = Hub > 後端推送 > 手動 `set_time`。
- **校正不再跳時間**：100 ms 以內的誤差以最多 500 ppm 的速度慢慢追上，時間戳不會倒退；超過 100 ms 才直接跳。
  - NTP 改為覆寫 ESP-IDF 的 `sntp_sync_time()`，取得的時間交給時鐘服務處理，不再直接 `settimeofday`。
- **封包時間戳改為掃描當下的時刻**，不再是組封包的時刻，少了一個掃描週期的偏差。封包格式不變。
- **相容性**：
  - 舊 Hub 或舊 Gateway 收到對時請求會直接丟掉；裝置連續 5 次沒收到回應就判定不支援，改每 5 分鐘再試。
  - HELLO／PAIRED／POLL 維持 1 byte，舊裝置照常配對。

### 新指令與設定

- `clock_sync`：立即重新同步。只啟動同步就回覆，結果之後出現在 `clock_status`。
- `clock_status`：時鐘狀態加上時鐘設定，回應只有幾百 bytes，適合輪詢。
- `set_clock_config`：設定以下三個值（也可用 `config_set`）：
  - `clock.ntp_server`：NTP 伺服器，預設 `pool.ntp.org`。
  - `clock.ntp_interval_s`：NTP 校正間隔，60–86400 秒，預設 600。
  - `clock.sync_interval_s`：與 Gateway／Hub 對時的間隔，5–3600 秒，預設 15。
- `set_time` 新增 `force`：明確的手動設定，會蓋過正在使用的 NTP／Hub／Gateway 時間。
- status 的 `clock` 區塊新增 `uncertainty_ms`、`step_count`、`pending_slew_ms`、`mode`，以及 `gateway`／`hub`／`sntp` 子區塊。

## 壓力校正

- **說明每顆感測器、每個等級被排除的原因**：草稿的 `draft_fit` 新增 `point_levels` 與 `points`，每顆感測器每個等級一個字元：
  - `u`：有用到
  - `s`：飽和（讀值頂到 ADC 上限）
  - `n`：無反應（讀值沒有高於基準值）
  - `b`：低於最低擬合壓力
  - `-`：還沒量
  - 判斷邏輯和實際擬合用的是同一個函式。
- **飽和時鎖在上限**：校正後的輸出不超過該感測器最高有效等級的壓力，讀值超出校正範圍後就固定在那個值。
  - 以前會照多項式外推；因為曲線往下彎，飽和的感測器壓越大，顯示的壓力反而可能變小。
  - **已經校正過的裝置，超出範圍時的輸出會改變。**
- **允許部分儲存**：只要有一顆感測器擬合成功就能儲存並啟用。擬合失敗的感測器輸出 0，不再因為一顆壞點讓整個校正存不了。
- `calibration_dump_fit` 每顆感測器新增 `max_x`、`max_pressure`（校正範圍的上限）。

## v2.2.C GCU LTS 改成 10×12

照板子總覽圖的「DO NOT USE PIN 11,17」，類比腳改為 IO1–10、掃描腳改為 IO18–45，不再使用 IO11、IO17。

- 存著舊 11×13 腳位設定的裝置，更新後會自動退回新的預設腳位。
- **已校正過的 v2.2.C 裝置要重新校正**：校正資料以「列 × 欄」的位置編號儲存，欄數改變後編號就對不上。
