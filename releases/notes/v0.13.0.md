# v0.13.0

## Changes

### New: devices in New Horizons Direct (ESP-NOW/Hub) mode can now receive OTA updates

- Previously, a device paired with a Hub over ESP-NOW (no WiFi of its own)
  had no way to receive firmware updates at all -- OTA only worked in
  `wifi_udp` mode.
- Once paired, the device now checks for an update exactly once at boot
  (mirrors the existing WiFi-mode `serviceAutoOta()` behavior -- no
  periodic recheck): it asks the Hub to fetch its OTA manifest on its
  behalf over a new small request/reply channel
  (`kEspNowFragTypeHubRequest`), and if a newer version is available, asks
  the Hub to relay the firmware binary itself, chunked over a new
  `kEspNowFragTypeOta` channel with per-chunk acknowledgment and
  idempotent duplicate-chunk handling (a lost ack causes the Hub to resend
  a chunk; the device recognizes the duplicate and only re-acks instead of
  writing it twice, which would otherwise corrupt the image).
- SHA256 verification and flash writing happen exactly as they already do
  for the WiFi/HTTP OTA path -- the Hub never touches `Update.*`, it's a
  pure byte relay; the device is solely responsible for verifying and
  applying the image, same as before.
- Real-hardware validated end-to-end: manifest fetch through a real Hub
  (against the real GitHub manifest URL), and a full 363-chunk relay of a
  real ~1.4MB firmware image, applied and rebooted successfully with a
  matching SHA256. Found and fixed a real bug during this validation (see
  the New-Horizons-Hub v0.2.0 release, which this depends on) where the
  Hub's relay code sent all fragments of a chunk in one unpaced burst,
  causing most of them to be silently dropped.
- Known limitation, not addressed this round: relay throughput is much
  slower than a rough estimate when the device is also streaming sensor
  data at full fps concurrently, since both share the same ESP-NOW
  airtime. Not a functional defect -- documented for now, may be revisited
  later (e.g. throttling sensor fps during an active relay).
- Not yet tested: multiple devices relaying/streaming at once (needs more
  device boards than are currently available).

## Also in this release

- New host-native unit tests (`tests_native/test_ota_chunk_codec.cpp`) for
  the OTA chunk sub-header parsing and idempotent-duplicate-chunk decision
  logic, split into a framework-free `OtaChunkCodec.h/.cpp` module
  specifically so it's testable without an Arduino toolchain (mirrors
  `EspNowFrame.h/.cpp`'s own reason for being framework-free).
