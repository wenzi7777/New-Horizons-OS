# v1.16.0

**App 事件改為跟著感測器串流送出，錄製時不必再輪詢。**

這是 v1.16.0-beta.1 的正式版，內容相同。

## 新功能

- App 產生的事件（例如 compass 的 `north`、`magnet`，姿勢偵測的 `slouch`）會放進感測器封包的擴充欄位（`app_event` TLV，見 `spec/PROTOCOL.md` 3.1）一起送出，通常一兩個 frame 內就送達。
  - 每筆事件記錄它發生在哪個 frame（`frame_seq`），Desktop 依此把時間換算成和主 CSV 同一套。
  - 一個封包最多帶 128 bytes 的事件，放不下的會留給下一個封包。
- `app_events` 的回覆多了 `"streaming":true`。Desktop v0.26.0 以上看到這個欄位，就不再每 0.5 秒輪詢，只在發現事件序號缺號（封包遺失）時補抓，另外每 5 秒檢查一次。
  - 經 Hub 時，指令通道不再被這些輪詢佔用。

## 相容性

- **請先把 Desktop 更新到 v0.26.1 以上，再讓裝置更新到這一版。** v0.26.0 以前的 Desktop 收到帶事件的封包時，網頁的即時串流會停住，要重新整理才恢復，錄製檔不受影響。v0.26.1 已修正。（beta 版說明寫「舊版 Desktop 會略過這些欄位」，這是錯的，在此更正。）
- 封包格式只是用上了原本保留的擴充欄位。Gateway 和 Hub 都是原樣轉送，不需要更新。
- 裝置內的事件緩衝區（32 筆）和 `app_events` 指令照舊。

## 實機驗證

- aaf4（v1.5.F）經正式環境錄製：3421 個 frame 連續，沒有缺號。23 筆事件的時間和主 CSV 同一個 frame 的時間完全相同，也沒有錄製開始前的事件。
- 掃描延遲和 v1.15.1 相當。
