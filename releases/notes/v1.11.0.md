# v1.11.0

**經 Hub 的大回應改成分頁傳送；壓力校正改成論文的擬合模型（升級後要重新校正）。**

## 經 Hub（ESP-NOW）的大回應改成分頁

以前一個回應最多 7680 B（32 片 × 240 B），超過就回 `response_too_large`。校正的 dump／擷取回應（9–33 KB）在每塊板子上都會失敗，`file_read_chunk`、`log_tail` 也可能失敗。

- 回應超過一個 frame 時，裝置先把整份回應暫存，送出第 0 頁；Hub 再用 `result_page` 一頁一頁拿。格式和 UDP 的 `result_chunk` 相同，由 Desktop 重組。
- 小回應的行為完全不變。
- 每頁帶 `rid`；裝置重建過的回應不會和舊的拼在一起（會回 `result_page_expired`）。
- 暫存在下一個指令到來或閒置 10 秒後釋放。
- **移除 Direct 模式的精簡版 `status`**：Hub 和 UDP 現在拿到同一份完整 status（約 13 KB，分 2 頁）。
- 回應分片的傳送拿掉固定的 15 ms 間隔，只靠「等上一片送達再送下一片」，每頁省約 15 ms。
- 序列埠會印 `paged_response rid= bytes= pages=` 與 `paged_response_last … elapsed_ms=`，可以看實際傳輸時間。

## 壓力校正：改成論文的模型（不相容）

和 E-Textiles 2026 論文的程式（`make_figures.py`）同一套邏輯，取代原本的三次插值，兩者不並存。

- **模型**：每個感測器用最小平方法擬合 p = a + b·√x + c·x。
  - x = 讀出曲線 ΔmV = c1·x + c2·x² 反解後的值；ΔmV 是相對基線的讀數。每顆 ADC（ADC1 = GPIO1–10、ADC2 = GPIO11–20）各有一組 c1、c2。
  - 預設 c1 = 1、c2 = 0，也就是直接用 mV 擬合。設成 AC14 的論文值就和論文完全相同。
  - 只用名目壓力 ≥ 最低擬合壓力（預設 3 kPa）、沒有削頂（ADC1 ≥ 3150 mV、ADC2 ≥ 3100 mV）的點；每個感測器至少 3 個點。
  - 輸出：x ≤ 0 時為 0；結果不小於 0；超過校正範圍時照多項式外插（和論文相同）。
- **每個感測器可以有不同的壓力組合**，所以逐點校正（例如用砝碼一次壓一格）可以用。
- **就緒條件**改成「每個感測器都擬合成功」。
- **擷取**改成：把時長切成約 0.5 s 的區塊，各取平均後取中位數。論文是逐幀中位數，但裝置記憶體放不下，所以用這個近似。
- **level 的名目與實測分開**：`level` 是名目壓力（同一個值再擷取會覆蓋），`reference` 是實際施加的壓力（擬合用這個）。
- **新指令**：
  - `calibration_set_fit`：設定最低擬合壓力、各 ADC 的 c1/c2 與削頂值。
  - `calibration_dump_fit`：輸出每個感測器的係數與擬合結果。
  - `calibration_set_reference`：擷取完成後再補上該 level 的實測壓力。
- **status 欄位**：新增 `fit`、`draft_fit`、`fit_settings`；移除 `levels_complete`、`legacy_missing_tare`。
- **不向後相容**：舊格式的校正資料開機時會被清除，裝置回到未校正，需要重新校正。
- 每格每幀的計算量和原本差不多，對 FPS 幾乎沒有影響。開機時序列埠會印 `[calibration] eval_us_per_cell=`。

## 其他

- `file_read_chunk` 的 `length` 限制在 1–32768，`offset` 不小於 0。以前負數會變成極大的長度，在檢查檔案大小前就先配置記憶體。
- `log_tail` 的 `max_lines` ≤ 0 時改用預設 50；以前等於讀整份 log。

## 驗證

- `tests/` 靜態測試全部通過；新增分頁、長度限制、擬合相關測試。
- `tests_native`：
  - 新增分頁器測試：最壞情況每頁 ≤ 7680 B、UTF-8 不被切斷、拼回等於原文。
  - 擬合測試：用論文 L3I8 兩個感測器的實際數據，結果和 numpy `polyfit` 一致（相對誤差 < 1e-4）。
- 5 塊板子的 release build 均通過。
- **本版尚未經過實機驗證**。

## 相容性

- 經 Hub 拿大回應需要 **Hub v0.6.0** 和 **Desktop v0.18.0**。舊 Hub 或舊 Desktop 拿大回應時，會和以前一樣失敗；小回應不受影響。
- 新校正流程與 fit 欄位需要 Desktop v0.18.0。
