# v0.16.0

## New: `Check update` / `Apply update` now work for New Horizons Direct (ESP-NOW) devices

A device paired to a Hub never joins WiFi, but `ControlServer`'s
`check_update` and `apply_update` handlers called `OtaManager` directly --
which fetches over HTTP. In Direct mode that could only ever fail, surfacing
in the Desktop app as an opaque `manifest_http_-1` and making it look like
Direct-mode devices couldn't be updated at all.

(The *boot-time* automatic update always worked: `EspNowOtaReceiver` asks the
Hub to fetch the manifest and relay the firmware over ESP-NOW. It just wasn't
reachable on demand, and reported no progress anywhere the UI could see.)

- `check_update` / `apply_update` now route through `EspNowOtaReceiver`'s
  Hub-relayed path whenever the device is in Direct mode. `OtaManager` is
  untouched and still serves the WiFi path.
- `EspNowOtaReceiver` gained on-demand `requestCheck()` / `requestApply()`.
  These are re-armable, unlike the deliberately boot-once automatic check --
  the "once per boot" rule is about automatic rechecks, not about refusing an
  explicit request. Both refuse (rather than corrupt anything) while a check
  or transfer is already in flight, so a double-click is safe.
- A check now stops after comparing versions and reports what it found;
  only an apply continues into the firmware relay.
- New `EspNowOtaReceiver::statusJson()` reports phase/version/url/error --
  and chunk progress during a transfer -- in the same shape as
  `OtaManager::lastStatusJson()`, so the Desktop app's existing update_state
  panel works unchanged. Previously a relay could run to completion with the
  UI showing nothing but `"phase": "idle"`.

Both commands are asynchronous, because the manifest lives behind a Hub
round trip: they start the operation and the outcome appears in
`update_state` on the next `status` poll. This matches how `apply_update`
already behaved on the HTTP path.

## Also in this release

- Requires `New-Horizons-Hub` v0.4.2 or newer on the paired Hub (no Hub-side
  change in this release -- the relay it already implements is what this
  makes reachable on demand).
