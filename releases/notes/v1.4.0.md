# v1.4.0

flow App 可以**在 OLED 上顯示內容，並接收 Action Button 的短按**。

## 為什麼

App 過去只能發事件和點 LED，結果必須回到 Desktop 才看得到。受試者身上的裝置如果能直接顯示
即時數值，並用按鈕切換畫面，很多現場確認就不需要電腦。

## 變更

- **新增 4 個 op**：`oled_text`（一行：標籤 + 數值）、`oled_bar`（一行：標籤 + 比例條）、
  `button`（每次短按只有一幀為 true）、`mod`（取餘數，用於換頁）。都是純量 op，每個 600 ns。
- **新增 capability `display`**；`button` 過去已存在但沒有 app 用得到，現在 flow App 可以宣告。
- **OLED 新增 `app` 頁面**：`set-oled` 的 `page` 設為 `app` 才會顯示 App 的內容；已安裝的 App
  不會自己佔用螢幕。多個 App 同時執行時，每一行由編號最小、有畫那一行的槽位取得。
- **畫圖不計入 App 的預算**：節點只記錄要顯示什麼，實際繪圖由韌體依 OLED 自己的 `update_hz`
  （最多 5 Hz）進行。畫面每幀依實際執行到的節點重建，所以關閉的 `gate` 那一行會變空白。
- **短按會傳給 App**（所有有按鈕的板子），同時照常執行原本設定的短按動作；長按是關機手勢，
  不會傳給 App。每次按下後至少有一幀為 false，連續兩幀內的兩次按壓也會被分開計數；沒有幀進來時
  最多保留 3 次。
- **v1.5.F 開啟 OLED 支援**：板上沒有面板，但接在外露 I2C 上的 SSD1306（0x3C / 0x3D）在 OLED
  開啟後會被偵測到。OLED 預設仍為 `off`。
- 數值格式化（四捨五入、對齊、比例條像素）集中在新的 `AppDisplay.cpp`。App Library 的
  `sdk/lib/oled.mjs` 逐步對應同一套運算，契約測試會把這個檔案編譯成本機程式逐值比對。

## 修正

- **OLED 刷新後 I2C 被降到 100 kHz**：Adafruit_SSD1306 每次傳輸後預設把匯流排時脈設為
  100 kHz，OLED 開著時 IMU、磁力計、電量計都會跟著變慢。現在傳輸時使用 400 kHz，結束後恢復
  板子原本的時脈（`NHOS_BOARD_I2C_HZ`）。

## 驗證

- 5 塊板子的 release build 均通過；`tests/` 靜態測試通過。
- App Library 的 171 項測試通過，其中包含與本版韌體原始碼的契約測試。
- **本版尚未經過實機驗證**：OLED 的 `app` 頁面、按鈕傳遞與 I2C 時脈修正需要在接有 SSD1306
  的 v1.0.F / v1.5.F 上確認。

## 相容性

- 使用 `show`、`bar`、`button()` 或 `%` 的套件需要本版本；App Library 會自動推算
  `min_os: v1.4.0`，舊韌體會以 `min_os` 拒絕安裝，不會等上傳後才以 `unknown_op` 失敗。
- 既有套件不受影響。
