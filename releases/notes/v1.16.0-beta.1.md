# v1.16.0-beta.1（測試版）

**App 事件改為跟著感測器串流送出，錄製時不必再輪詢。**

這是測試版，只發布在 beta 通道（`*-beta.json`）。

## 新功能

- App 產生的事件（例如 compass 的 `north`、姿勢偵測的 `slouch`）會放進感測器封包的擴充欄位（`app_event` TLV，見 `spec/PROTOCOL.md` 3.1）一起送出，通常延遲一兩個 frame 就送達。
  - 事件記錄的是它發生的那個 frame（`frame_seq`），Desktop 依此換算成和主 CSV 相同的時間。
  - 一個封包最多帶 128 bytes 的事件，放不下的留給下一個封包。
- `app_events` 的回覆多了 `"streaming":true`。Desktop v0.26.0 看到這個欄位就不再每 0.5 秒輪詢，只在發現事件序號缺號（封包遺失）時補抓，另外每 5 秒檢查一次。
  - 經 Hub 時，指令通道不再被這些輪詢佔用。

## 相容性

- 封包格式只是用了原本就保留的擴充欄位。Gateway 和 Hub 原樣轉送，不需要更新。
- 搭配 Desktop v0.26.0 以上，事件會從串流寫入錄製檔。
- 舊版 Desktop 會略過這些欄位，仍然用輪詢取得事件。但後端剛重開、還不知道裝置矩陣大小的那幾秒內，帶事件的封包會被丟棄，所以建議一併更新 Desktop。
- 裝置內的事件緩衝區（32 筆）和 `app_events` 指令都不變。
