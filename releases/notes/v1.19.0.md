# v1.19.0

**系統監視器：可以結束、啟動工作與服務，查看 FreeRTOS 執行緒與每核 CPU。**

## 操作（只在本次開機有效）

所有停止都不寫入 NVS,重開機後全部恢復原狀。保護規則由韌體自己執行，不依賴介面。

- **工作**:`task_stop` / `task_start` 結束或啟動排程器的工作;`task_set_period` 調整執行頻率(`period_us`,0 = 每次迴圈,`"default"` 恢復原值，上限 10 秒)。
  - 受保護、會回 `task_protected`:所有電源相關工作，以及 `control`、`control_udp`、`wifi`、`espnow`、`heartbeat`、`findme`、`time_heartbeat`、`stream_queue`、`power_transition`——停掉會讓裝置失聯或電源失控。
  - `scan_stream` 可以停止，但頻率由 `set_scan_timing` 決定，不能另外調整(`period_fixed`)。
- **服務**:`service_stop` / `service_start`,只開放 `scanner` 和 `imu`。
  - 停止後不再做健康檢查與自動重試；從省電模式恢復、離開維護模式、修改矩陣布局都不會把它偷偷啟動回來。
  - `imu` 的停止不會改動 `set_imu` 的設定；用 `set_imu` 存「開」等同明確啟動。
- **App**:`app_stop` / `app_start`,不寫入 NVS 的「結束工作」(`app_disable` 仍是會保存的開關)。

## 監視

- **`thread_list`**:列出 FreeRTOS 執行緒(loopTask、WiFi、esp_timer、IDLE 等)的狀態、優先權、堆疊剩餘最低值、CPU 佔比，以及每核負載。唯讀，不能停止執行緒。第一次呼叫沒有比較基準,CPU 回傳 null。
- **`sysmon`**:一次回傳工作、服務、App、記憶體、掃描、執行緒與 airtime。透過 Hub(ESP-NOW 每台一次只能一個指令)時，監視器每秒只需要 1 個指令，原本是 5 個。回覆超過單一 frame 時沿用 `result_page` 分頁。
- `task_list` 新增 `state`、`protected`、`fixed_period`、`default_period_us`;`service_list` 新增 `stoppable`、`operator_stopped`;`app_list` 新增 `governor`(App 預算調節器);App 狀態新增 `stopped`。

## App 套件

- 認得新的套件種類 **panel**(可操作的 readout,由 Desktop 繪製)。和 readout 一樣只存在登錄表，不會在裝置上執行。
- 套件大小上限從 4096 提高到 8192 位元組(系統監視器 panel 約 5.4 KB)。只在安裝與啟用時短暫多用約 16 KB heap,不常駐。

## 相容性

- 搭配 Desktop v1.3.0 的系統監視器使用;舊版 Desktop 仍可使用既有功能。
- 新指令都在 `commands` 指令表中,Desktop 會依指令表隱藏舊韌體沒有的操作。
- 尚未實機驗證:`sysmon` 經 ESP-NOW 的實際回覆大小與分頁次數。
