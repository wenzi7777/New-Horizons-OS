# v1.15.0

**指令改成一張表、裝置回報自己支援的指令、`status` 幾乎不再拖慢掃描；平台規格與共用程式碼各只有一份來源。**

這是 v1.15.0-beta.1～beta.4 的正式版。

## 指令表與 `commands`

- 所有控制指令改成一張表（`ControlCommandTable.cpp`）：名稱、處理函式、旗標、說明。維護模式的檢查由表上的旗標統一處理。
- 新增唯讀指令 `commands`：回傳每個指令的名稱、說明與旗標（`maintenance`、`heavy`、`quiet`、`internal`、`status_snapshot`）。`capabilities` 新增 `command_schema_hash`、`command_count`。Desktop v0.23.0 起據此判斷可用指令，韌體以後新增的指令不需要更新 Desktop 就能使用。
- **行為修正**：`exit_maintenance` 在一般模式下改回 `maintenance_required`（以前什麼都不做卻回成功）。

## 掃描更穩定

- 重指令（`status`、`query`、`storage_status`、`commands`）經 UDP 收到時，先回 ack，再等掃描剛結束、空檔夠大時才執行（最多延後約 40 ms）。
- 排程器：掃描一到期就優先執行，不再等排在後面的工作（例如每次約 2.5 ms 的 IMU 讀取）。`status.scheduler`、`task_list` 新增 `urgent_runs`。
- 大回覆不再多複製一份；排程器狀態與 MAC 位址的產生也變快。
- v1.5.F（5×5、60 fps）實測：單次 UDP `status` 讓掃描晚開始的時間從約 8 ms 降到約 0.7 ms；每秒輪詢 `status`，晚 2 ms 以上的掃描從 1.72% 降到約 0.3%。

## Direct 模式（經 Hub）

- 檢查更新時，已是最新版也會回報 manifest 提供的版本與網址（以前只有 `current`、版本空白）。

## 單一來源

- App 的 op 表、capability 位元、欄位名稱與顏色，由 App Library 的 `opset.mjs` 產生成 `AppContract.h`。
- 線上格式常數（埠號、封包、對時）只寫在 `spec/wire.json`，產生韌體、Hub、Desktop、Gateway 的常數檔。
- 新增 `spec/PROTOCOL.md`；`spec/commands.md`、`spec/config.md` 由韌體的表自動產生。
- 與 Hub 共用的程式碼改成同一份函式庫 `firmware/libraries/nhos_core`。自行用 `arduino-cli` 編譯時要加 `--library firmware/libraries/nhos_core`（腳本已帶）。

## 相容性

- 封包、指令名稱、參數與回覆格式都沒變（除了上面的 `exit_maintenance`）。舊版 Desktop 仍可使用。
- 建議搭配 Desktop v0.24.4、Hub v0.10.0。
