# v2.0.0

**Apps now run on an on-device bytecode virtual machine (NHVM/1) instead of the flow-graph interpreter; behaviour is unchanged, but apps need their 2.0.0 versions.**

## The app VM

- Every app runs the bytecode image the App Library compiles (the package's `vm`). The flow operators became the VM's native instructions and behave value for value the same (the App Library's C/JS conformance test compares them bit for bit).
- The device's verifier checks an image at install and at activation: jump targets, stack depth, arena indices, declared capabilities. Any mismatch refuses it.
- Each run has a time slice: a handler that runs past its allocation is suspended and resumed on the next delivery, never delaying the scan; frames it missed meanwhile are reported as a `frames_skipped` event, not dropped silently.

## Memory

- The four app slots share one 4 KB static pool (every Library app takes under 640 B), and nothing is taken from the heap while running. An image that does not fit is refused at activation with `app_pool_exhausted`.
- The interpreter's hot path runs from IRAM: run from flash, most of its time went to cache misses. On a v2.0.F, four apps take 263 µs per frame together (370 µs on v1.23.0), with static RAM about the same as before.
- `memory_status` adds `heap_min_largest_free_block`: the lowest the largest free block has been, to watch for fragmentation.

## Compatibility

- App packages built before v2.0.0 have no image and show as `needs_update`: reinstall the 2.0.0 version from the App Store.
- The app version changes, so `persist` counts start again from 0.
- 2.0.0 apps need firmware v2.0.0 or later.
