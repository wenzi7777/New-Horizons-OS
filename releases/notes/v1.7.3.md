# v1.7.3

**修正：自動 OTA 可能讓裝置卡進 safe_maintenance，新韌體一再被退回、又一再重新下載。**

## 為什麼

一台 v1.5.F（AC14）更新到 v1.7.2 時開機很慢，而且進了 safe_maintenance，紀錄顯示 `rolled_back_from=v1.7.2`。
裝置沒有記錄到任何 crash，v1.7.2 本身也能正常開機並確認，問題出在開機時自動 OTA 的計數方式：

- 自動 OTA 在 setup 裡、`markBootOk()` 之前執行。所以舊韌體下載完新版後重開的那次開機，會被算成一次「開機失敗」。
- 下載約 20 秒，LED 一直停在 OTA 燈號，看起來像當機；這期間按 RST 或斷電，也各算一次失敗。
- 連續 3 次失敗後，新韌體的第一次開機就會進 safe_maintenance。在 safe_maintenance 下新韌體刻意不確認，
  所以下一次重開時 bootloader 會把它退回舊版，舊版又自動下載新版，形成循環。

另外，`rolled_back_from` 一旦寫入就永遠不會清除；即使之後同一版已經確認成功，status 仍會一直顯示曾經退回。

## 變更

- **自動 OTA 開始下載前，先把這次開機標記為成功。** 能以已確認的韌體連上 Wi-Fi、走到 OTA 檢查，就代表這次開機是健康的。
  自動 OTA 的重開、下載途中被中斷，都不再算成開機失敗。
  尚未確認的新韌體本來就會跳過自動 OTA（`auto_ota_deferred`），所以新韌體失敗時自動退回的保護不受影響。
- **新韌體確認成功時，清除 `rolled_back_from`。** 確認成功的更新取代了先前的退回紀錄。

## 驗證

- 5 塊板子的 release build 均通過；`tests/` 靜態測試全部通過（新增 2 個檢查）。
- **本版尚未經過實機驗證**：AC14 自動更新到 v1.7.3 後，應該以 normal 模式開機，而且 `rolled_back_from` 為空。

## 相容性

- 只改開機計數和退回紀錄，指令與回應格式不變。Desktop 不需要更新（v0.14.1 即可）。
- 從舊版更新到 v1.7.3 的這一次，還是由舊版執行自動 OTA，所以仍然照舊版的方式計數；v1.7.3 之後的更新才會用新規則。
