# v1.7.5

**修正：區網裡有多台 Gateway 時，開機後偶爾閃橙燈（ScanWarning）。** 掃描本身沒有問題。

## 為什麼

一台 v1.5.F（AAF4）開機後偶爾閃兩下橙燈再恢復綠燈。同時監看序列埠和 `scan_health` 後抓到：

1. 開機後的 discover 有兩台 Gateway 回應（.90 與 .99，priority 相同）。
2. 裝置先接受 .90，80 ms 後又接受 .99，串流目標跟著切換。在 discover 後的讀取窗口內每個 offer 都會被接受，
   窗口外只要 priority 相同也會被搶走，所以最後回應的那台會贏。
3. 送往新目標的前幾幀，`endPacket()` 失敗了 4 次。最可能的原因是新目標的位址還在解析；60 fps 下 4 幀約 66 ms。
4. `ScanWarning` 只在還沒連上 Gateway 時忽略失敗，這 4 次發生在連上之後，所以閃了橙燈。之後掃描維持 59 fps、沒有再失敗。

是否失敗取決於位址解析和第一幀誰先到，所以時有時無。

## 變更

- **每一輪 discover 只接受第一台回應的 Gateway**，之後就留在這台。
  - 之後只有三種情況會接受新的 offer：同一台 Gateway 重新回應、priority 嚴格更高、正在進行 Gateway 移轉。
  - 開機時仍可用第一個回應取代上次開機記住的 Gateway。
  - 多台 priority 相同的 Gateway 時，每次開機連到哪台取決於哪台先回應；每台都會轉發到 Backend，使用上沒有差別。
- **連上 Gateway 後的前 2 秒，UDP 送出失敗不觸發 ScanWarning。**
  第一次連上、換到另一台 Gateway、WiFi 重新連線後都適用。掃描 overrun 不受影響，照樣立刻觸發警告。

## 驗證

- 5 塊板子的 release build 均通過；`tests/` 靜態測試全部通過（新增 3 個檢查）。
- **本版尚未經過實機驗證**：多台 Gateway 的環境下連續重啟，開機紀錄應該只出現一次 `findme_offer_accepted`，且不再閃橙燈。

## 相容性

- 指令與回應格式不變。Desktop 不需要更新（v0.14.2 即可）。
- Gateway 移轉（`findme_switch_gateway`）的行為不變。
