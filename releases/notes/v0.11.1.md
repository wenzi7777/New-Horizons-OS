# v0.11.1

## Fixes

### IMU status now reports the real sample rate

- `ImuManager::statusJson()` previously reported a hardcoded, unused
  `sample_rate_hz` field that was always `100`, regardless of the actual
  polling interval. IMU sampling has no independent ODR — it is a polled
  interval slaved to the matrix scan rate (`imu.setServiceIntervalUs(scanner.scanIntervalUs())`),
  so the real rate tracks whatever `set_scan_timing` last configured (default
  60 fps → ~60 Hz), and the stale constant never reflected that.
- `sample_rate_hz` in the `imu` status object is now derived live from the
  actual service interval, so it correctly tracks changes made via
  `set_scan_timing`. This behavior (IMU rate follows scan rate) is
  intentional and unchanged — only the reported value was wrong.

### Flash scripts could upload a stale binary from the wrong board variant

- `arduino-cli upload` does not compile the sketch; without an explicit
  `--build-path`/`--input-dir`, it flashes from the sketch's shared build
  cache, which is keyed only by `vendor:arch:board` and ignores
  `FlashSize`/`PartitionScheme` and any `-DNHOS_BOARD_*` build-property flags.
  A stale compile of a different board variant left in that shared cache
  could silently get flashed instead of the one actually requested.
- `flash_arduino_firmware.sh` (v1.0.F) now compiles into its own dedicated
  build path immediately before uploading from that same path.
- Added dedicated flash scripts for the three GCU LTS variants —
  `flash_arduino_firmware_gcu_v21_lts.sh`, `flash_arduino_firmware_gcu_v22c_lts.sh`,
  `flash_arduino_firmware_gcu_v23d_lts.sh` — each compiling into its own
  build path with the correct `-DNHOS_BOARD_*` flag before uploading.

## Verification

- ESP32-S3 Arduino compile for all four board models:
  - `VD-CTL/R v1.0.F 2026.4`
  - `VD-CTL/R v2.3.D GCU LTS`
  - `VD-CTL/R v2.2.C GCU LTS`
  - `VD-CTL/R v2.1 GCU LTS`
- Confirmed via the desktop backend's mock `VD-CTL/R v2.3.D GCU LTS` device:
  `imu.sample_rate_hz` reports the live value (60 at default scan timing) and
  updates immediately when `set_scan_timing` changes the target FPS.
