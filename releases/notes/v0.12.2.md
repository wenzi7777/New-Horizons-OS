# v0.12.2

## Changes

### New: brand-new devices can pair directly with a Hub, no Gateway needed

- Previously, switching a device to ESP-NOW/Hub mode required a
  `set_transport` command relayed through a WiFi Gateway or direct UDP --
  a factory-fresh device that had never been reachable via a Gateway had
  no way to reach a Hub at all.
- `EspNowPairing` now falls back to broadcasting its HELLO to
  `FF:FF:FF:FF:FF:FF` (instead of failing) whenever `hub_mac` is
  empty/invalid, while channel-hopping the same way it already does to
  find a known Hub's channel. Any Hub in range replies exactly as it
  would to a unicast HELLO -- the Hub firmware needed zero changes. Once
  a reply is seen, the discovered MAC is saved and the device reboots
  into the normal, unmodified unicast HELLO/PAIRED/POLL flow.
- The device's own WiFi setup portal (the SoftAP page a factory-fresh
  device already boots into) has a new "Connection mode" selector: WiFi
  (default, existing) vs Direct/Hub. Picking Direct/Hub needs no SSID,
  password, or Hub MAC address -- just save and the device finds a Hub on
  its own.
- If no Hub is found within 2 minutes, the device automatically falls
  back to the WiFi setup portal on its next boot rather than hanging
  forever -- this also fixes a pre-existing gap where an `espnow`-mode
  device with no `hub_mac` had no reachable UI at all.
- Real-hardware validated: both the underlying discovery mechanism and
  the actual portal-driven user flow (picking Direct/Hub from the setup
  page) found a real Hub, learned its MAC, and paired successfully on the
  first attempt. Not yet tested with multiple Hubs or multiple
  simultaneously-discovering devices (needs more boards than are
  currently available) -- single Hub, single device is the validated
  case so far.
