# v1.18.0

**修正：v1.5.F でバッテリー残量が 100% を超える、または 100% に届く前に「充電完了」と表示される問題。**

## 原因

- MAX17048 燃料ゲージの 100% は内蔵の汎用モデル上の電圧点で、充電器が実際に満充電を終えたかどうかは分かりません。BQ25180 が充電完了(4.2 V、電流が終止値まで低下)を報告した時点で、ゲージは 92% と読むことも 108% と読むこともあります。
- 旧ファームウェアはゲージの生の値をそのまま送っており、上限がありませんでした。
- ゲージの再同期(quick-start)は USB 接続中に行われることが多く、充電電流で電池電圧が持ち上げられるため初期残量が高く見積もられ、その後 100% を超えていました。

## 修正内容

- **充電器の「充電完了」を 100% の基準にしました。** 充電中から充電完了に移るたびに、その時点のゲージ値を記録し、以降の残量はこの比率で換算して 0–100% に収めます。90–110% の範囲外の値はゲージの異常とみなして採用しません。
- **USB 接続中に満充電になったら 100% に固定**し、USB を抜くまで維持します。補充電で数字が上下しなくなります。
- **電池情報に依存しないので、電池を交換しても安全です。** 換算比率は RAM にのみ保持し、NVS には書き込みません。再起動、ゲージの電源リセット通知(STATUS.RI、電池を抜くと立つ)、急な電圧変化、手動の再同期、電池設定の変更のいずれでもクリアして学習し直します。容量はパーセント計算に関与しません。
- **再同期の前に充電を一時停止します。** USB 接続中は充電を 1.5 秒止めて電圧を落ち着かせてから quick-start を行い、新しい値を読んだら充電を再開します。失敗・タイムアウト・モジュール再起動のときは必ず充電を再開します。動作中に電池を抜き差しした場合(RI)も、この方法で自動的に再同期します。
- 診断用にバッテリー状態へ `soc_raw_centi_percent`(ゲージの生値)、`soc_full_centi_percent`、`soc_full_learned`、`charging_paused_for_sync` を追加しました。再同期の理由に `gauge_reset` を追加しました。

## 互換性

- 燃料ゲージを持つ v1.5.F にのみ影響し、他のボードの動作は変わりません。ストリームパケットの形式は変わらず、送る残量が換算後の値になります。
- Desktop v1.2.3 と組み合わせる想定です(旧ファームウェアが 100% 超を報告しても表示を制限します)が、Desktop を更新しなくても動作します。
- 実機では未検証です：充電の一時停止には BQ25180 `ICHG_CTRL` の bit7(`CHG_DIS`)を使います。書き込み後に読み返して確認し、失敗した場合は一時停止しない従来の動作に戻ります。
