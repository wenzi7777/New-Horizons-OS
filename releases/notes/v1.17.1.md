# v1.17.1

**修正：Hub（ESP-NOW）模式下，裝置在維護模式中斷電重開後，雖然已和 Hub 配對成功，Web UI 卻看不到這台裝置。**

## 修正

- **維護模式的裝置重開後，Web UI 能找到它了。** Hub 只會從裝置的感測資料封包讀出 device_uid，配對用的 HELLO 封包裡沒有這個值。維護模式會在重開後繼續生效，這段期間掃描停止，裝置一個資料封包都不送。結果只要 Hub 重開過，或裝置離線超過約 30 秒、Hub 回收了它的位置，Hub 就不知道這台裝置的 ID，也不會回報給 Backend。序列埠雖然顯示 `[espnow_pairing] paired`，Web UI 裡卻看不到裝置，也無法送 `exit_maintenance`。以前只能先切回 Wi-Fi 直連、退出維護，再切回 Hub。
- 現在裝置在 ESP-NOW 模式下，只要已配對 Hub 而且沒有在掃描，就會每 5 秒透過 Hub 送一次 heartbeat（24 B，只有標頭），跟 Wi-Fi 模式的 heartbeat 相同。Hub 從 heartbeat 讀到 UID 後，裝置約 5 秒內就會出現在 Web UI。
- 沒設定矩陣 layout 的裝置在 Normal 模式下同樣不會掃描，以前也有這個問題，這次一起修好。
- 掃描中不送 heartbeat：這時資料封包本來就帶 UID，而 ESP-NOW 傳輸只有一格緩衝，heartbeat 會擠掉感測資料。

## 相容性

- 只改裝置韌體，Hub、Gateway、Desktop 都不用更新。Backend 原本就能處理經 relay 轉來的 heartbeat。
- Wi-Fi 模式的行為不變。串流封包格式不變。
- 已經卡在維護模式、Web UI 看不到的裝置收不到 OTA，需要先用原本的方法（切回 Wi-Fi、退出維護）處理一次再更新。
