# v0.12.0

## Changes

### New: ESP-NOW transport option ("New Horizons Direct")

- Device firmware can now stream sensor data over ESP-NOW to a New Horizons
  Hub instead of WiFi/UDP to a Gateway, for sites where running a Gateway on
  the LAN isn't practical. Selected via a new `set_transport` command
  (`mode=espnow` + the Hub's MAC, or `mode=wifi_udp` to switch back), stored
  in `DeviceConfig.transport` and applied on next boot.
- New abstraction: `StreamTransport` (interface) / `UdpStreamTransport`
  (mechanical extraction of the existing WiFi/UDP send path, zero behavior
  change) / `EspNowStreamTransport` (new, paired with `EspNowPairing`'s
  HELLO/PAIRED/POLL state machine) — `newhorizons_os.ino` now sends every
  frame through whichever transport is active rather than calling
  `WiFiUDP` directly.
- `wifi_udp` mode (the existing default) is unaffected: this is purely an
  additional opt-in transport, not a replacement. Regression-tested on real
  hardware to confirm zero behavior change when `espnow` mode isn't
  selected.
- The New Horizons Hub firmware itself (the ESP-NOW receiving side) now
  lives in its own repo, `New-Horizons-Hub`, rather than as a build variant
  here — see that repo's README for its own release history.
