# v1.16.1

**修正：ADC2 那幾條 A 線壓到飽和時讀到約 4983 mV（實際上不可能超過 3.3 V），現在會停在約 3.1 V；`scan_health` 新增 ADC 校正點與讀取錯誤計數。**

## 修正

- **ADC2 飽和時不再讀到約 5 V。** 以前韌體用 Arduino core 的 `analogReadMilliVolts()` 換算，它內部用的是 ESP-IDF 的 ESP32-S3 曲線校正。這套校正計算二次項時，用的 uint64 乘法會溢位：電壓到了約 3532 mV（ADC2）或 3770 mV（ADC1）以上，那一項就變成約 0，原本要扣掉的約 1840 mV 沒有扣到。結果最上面幾個讀數會從約 3120 mV 直接跳到 4969–4983 mV，中間沒有任何值。會不會碰到，要看每顆晶片出廠燒在 eFuse 裡的校正點：ADC2 的校正點低於 986 就會。ESP-IDF v6.0.1 也還沒修。
- 現在韌體改成讀 raw 值，自己換算：照 IDF 的算法逐項計算，只有會溢位的那一項改用浮點。IDF 本來算對的範圍，結果逐位元相同，所以已存的 tare 和校正資料都不受影響。只有原本溢位的那一小段改成正確、連續的值，飽和時約 3.1 V。
- **ADC2 讀取失敗時沿用上一個值。** ADC2 和 Wi-Fi 共用硬體，讀取時如果被 Wi-Fi 佔用，以前會讀到 0（`analogReadMilliVolts`），現在該格會保留上一次的讀數，並把錯誤次數加 1。

## 影響的板子

- v1.5.F：A10–A13（GPIO11–14）。
- GCU V2.3.D：GPIO11–15。
- v1.0.F、GCU V2.1、V2.2.C 的 A 線全部接在 ADC1。只有 ADC1 校正點低於 924 的晶片，才會在飽和附近碰到同樣的溢位，現在也一併修正。

## 新增

- `scan_health`（也包含在 `status` 裡）多了兩個欄位：
  - `adc_cal_digi: [ADC1, ADC2]` —— 這顆晶片的 eFuse 校正點（出廠時讀 850 mV 的讀數）。0 表示沒有校正資料，韌體會退回 core 原本的換算。
  - `adc_read_errors: [ADC1, ADC2]` —— 開機以來讀取失敗、改用上一個值的次數。

## 相容性

- 串流封包格式不變，`scan_health` 只有新增欄位。
- 2026-10-19 已在 v1.5.F 實機確認：飽和停在約 3.1 V，ADC1 的讀數不變，讀取錯誤為 0。
