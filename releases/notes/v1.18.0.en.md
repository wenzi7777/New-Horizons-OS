# v1.18.0

**Fix: on v1.5.F the battery level could go above 100%, or show "charge done" before reaching 100%.**

## Cause

- The MAX17048 fuel gauge's 100% is a voltage point in its built-in generic model; it does not know when the charger has actually finished. When the BQ25180 reports charge done (4.2 V, current down to the termination level), the gauge may read 92% or 108%.
- Older firmware sent the gauge's raw value as is, with no upper limit.
- Gauge resyncs (quick-start) mostly ran with USB connected. The charge current lifts the battery voltage, so the starting level was estimated too high and later climbed past 100%.

## Fix

- **The charger's "charge done" now defines 100%.** On every transition from charging to charge done, the gauge reading at that moment is recorded and later levels are scaled by it, limited to 0–100%. A reading outside 90–110% is treated as a gauge error and ignored.
- **While USB is connected and the battery is full, the level stays at 100%** until USB is unplugged, so top-up charging no longer makes the number jump.
- **No battery information is needed, so swapping batteries is safe.** The scale lives only in RAM and is never written to NVS. It is cleared and learned again on reboot, when the gauge reports a power-on reset (STATUS.RI, set when the battery is pulled), on a sudden voltage jump, on a manual resync, and when the battery setting changes. Capacity plays no part in the percentage.
- **Charging is paused before a resync.** With USB connected, charging pauses for 1.5 s so the voltage settles, then quick-start runs; charging resumes once a new reading comes in. Failure, timeout or a module restart always resumes charging. Pulling and swapping the battery while running (RI) also triggers a resync done this way.
- New battery status fields for diagnostics: `soc_raw_centi_percent` (raw gauge value), `soc_full_centi_percent`, `soc_full_learned`, `charging_paused_for_sync`. New resync reason: `gauge_reset`.

## Compatibility

- Only affects v1.5.F, the board with a fuel gauge; other boards behave as before. The stream packet format is unchanged; the level sent is now the scaled value.
- Pairs with Desktop v1.2.3 (which also caps the display when older firmware reports over 100%), but works without updating the Desktop.
- Not yet verified on hardware: pausing charge uses BQ25180 `ICHG_CTRL` bit 7 (`CHG_DIS`). The write is read back to confirm; on failure the firmware falls back to the old behaviour without pausing.
