# v1.18.0

**修正:v1.5.F 的電量會超過 100%,或還沒到 100% 就顯示「充電完成」。**

## 原因

- MAX17048 電量計的 100% 是內建通用模型的一個電壓點，不知道充電器何時真的充滿。BQ25180 報「充電完成」(4.2 V、電流降到終止值)時，電量計可能讀 92%,也可能讀 108%。
- 舊韌體把電量計的原始值直接送出，沒有上限。
- 重新校準(quick-start)多半在接著 USB 時進行，充電電流把電池電壓墊高，起始電量被估高，之後就會超過 100%。

## 修正

- **以充電器的「充電完成」作為 100%。** 每次從充電中進入充電完成時，記下當下的電量計讀數，之後的電量依此比例換算，並限制在 0–100%。讀數超出 90–110% 視為電量計異常，不採用。
- **接著 USB 且已充滿時固定顯示 100%**,直到拔掉 USB;充電器補電時數字不再上下跳動。
- **不依賴電池資訊，換電池也安全。** 換算比例只存在 RAM,不寫入 NVS;重開機、電量計回報斷電重置(STATUS.RI,拔電池時會設起)、電壓突然跳變、手動重新校準、修改電池設定，都會清除並重新學習。容量不參與百分比計算。
- **重新校準前先暫停充電。** 接著 USB 時先暫停充電 1.5 秒讓電壓回穩，再做 quick-start,讀到新值後恢復充電；失敗、逾時或模組重啟一律恢復充電。執行中拔換電池(RI)也會自動以這個方式重新校準。
- 電池狀態新增 `soc_raw_centi_percent`(電量計原始值)、`soc_full_centi_percent`、`soc_full_learned`、`charging_paused_for_sync` 供診斷；重新校準原因新增 `gauge_reset`。

## 相容性

- 只影響有電量計的 v1.5.F;其他板子行為不變。串流封包格式不變，送出的電量改為換算後的值。
- 搭配 Desktop v1.2.3(舊韌體回報超過 100% 時也會限制顯示),但不更新 Desktop 也能用。
- 尚未實機驗證：暫停充電使用 BQ25180 `ICHG_CTRL` bit7(`CHG_DIS`),寫入後會讀回確認，失敗則退回不暫停的舊做法。
