# v2.3.1

**WiFi モードのデバイスで使える空きメモリ（heap）が約 44 KB 増え、最大連続ブロックはおよそ 2 倍になりました。**

## メモリ

- ESP-NOW（New Horizons Direct）のペアリング、ストリーム、OTA 中継、無線スケジューリング用のバッファ（合計約 44 KB）は、これまで転送モードにかかわらず常に確保されていました。今後は ESP-NOW モードで起動したときだけ確保し、WiFi / UDP モードのデバイスではこの分を heap として使えます。
- v2.0.F での実測（WiFi、14×10、App なし、各 10 分）：空き heap の中央値 105.0 → 159.8 KB、最大連続ブロック 36.9 → 73.7 KB。スキャン fps とフレーム欠落は変わりません。
- ESP-NOW モードの使用量の合計は変わりません。バッファが静的メモリから起動時の確保に移っただけなので、`memory_status` の `heap_free` は以前より約 44 KB 少なく表示されますが、正常です。
- ESP-NOW モードの起動時に確保できなかった場合（メモリ不足。通常は起こりません）、デバイスは WiFi モードで起動し（保存済みの WiFi があれば接続、なければ設定ページ）、`espnow_alloc_failed` を記録します。

## 互換性

- WiFi モードでは `status` / `sysmon` の `airtime` は `{}`、機能一覧の `airtime_arbiter` は `false` になります（このスケジューラは ESP-NOW 専用です）。
- プロトコルとコマンドに変更はなく、現行の Desktop、NH Studio / Pocket / headless、Hub と併用できます。
