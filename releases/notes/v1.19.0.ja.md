# v1.19.0

**システムモニター：タスクとサービスの終了・開始、FreeRTOS スレッドとコアごとの CPU 表示に対応しました。**

## 操作(今回の起動中のみ有効)

停止はどれも NVS に保存されず、再起動ですべて元に戻ります。保護のルールは UI ではなくファームウェア自身が適用します。

- **タスク**:`task_stop` / `task_start` でスケジューラーのタスクを終了・開始し、`task_set_period` で実行頻度を変更します(`period_us`、0 = ループごと、`"default"` で元の値、上限 10 秒)。
  - 保護されていて `task_protected` を返すもの：電源関連のすべてのタスクと `control`、`control_udp`、`wifi`、`espnow`、`heartbeat`、`findme`、`time_heartbeat`、`stream_queue`、`power_transition`。止めるとデバイスと通信できなくなるか、電源制御が失われます。
  - `scan_stream` は停止できますが、頻度は `set_scan_timing` で決まるため個別には変更できません(`period_fixed`)。
- **サービス**:`service_stop` / `service_start`。対象は `scanner` と `imu` のみです。
  - 停止中はヘルスチェックも自動再試行も行いません。省電力からの復帰、メンテナンスモードの終了、マトリクス配置の変更でも勝手に再開しません。
  - `imu` の停止は `set_imu` の設定を変えません。`set_imu` で「オン」を保存すると明示的な開始として扱います。
- **アプリ**:`app_stop` / `app_start`。NVS に保存しない「タスクの終了」です(`app_disable` は引き続き保存されるスイッチです)。

## モニター

- **`thread_list`**:FreeRTOS スレッド(loopTask、WiFi、esp_timer、IDLE など)の状態、優先度、スタック残量の最小値、CPU 使用率、コアごとの負荷を表示します。読み取り専用で、スレッドは停止できません。初回は比較対象がないため CPU は null を返します。
- **`sysmon`**:タスク、サービス、アプリ、メモリ、スキャン、スレッド、airtime を 1 回の応答で返します。Hub 経由(ESP-NOW は 1 台につき同時に 1 コマンド)でも、モニターは毎秒 5 コマンドから 1 コマンドになります。1 フレームを超える応答は従来どおり `result_page` で分割します。
- `task_list` に `state`、`protected`、`fixed_period`、`default_period_us`、`service_list` に `stoppable`、`operator_stopped`、`app_list` に `governor`(アプリ予算の調整器)を追加しました。アプリの状態に `stopped` を追加しました。

## アプリパッケージ

- 新しいパッケージ種別 **panel**(操作できるリードアウト。Desktop が描画)を認識します。リードアウトと同じく登録表にだけ保存され、デバイス上では実行されません。
- パッケージサイズの上限を 4096 から 8192 バイトに引き上げました(システムモニターの panel は約 5.4 KB)。インストールと有効化のときだけ一時的に約 16 KB のヒープを使い、常駐はしません。

## 互換性

- Desktop v1.3.0 のシステムモニターと組み合わせて使います。旧バージョンの Desktop でも既存の機能は使えます。
- 新しいコマンドはすべて `commands` 一覧に含まれ、Desktop は旧ファームウェアにない操作を一覧に従って隠します。
- 実機では未検証：ESP-NOW 経由での `sysmon` の実際の応答サイズと分割回数。
