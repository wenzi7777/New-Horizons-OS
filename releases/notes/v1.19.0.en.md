# v1.19.0

**System monitor: end and start tasks and services, and see FreeRTOS threads and per-core CPU.**

## Control (this boot only)

Nothing is saved to NVS; a reboot puts everything back. Protection is enforced by the firmware itself, not by the UI.

- **Tasks**: `task_stop` / `task_start` end or start a scheduler task; `task_set_period` changes how often it runs (`period_us`, 0 = every loop pass, `"default"` restores it, at most 10 s).
  - Protected, answering `task_protected`: every power task, plus `control`, `control_udp`, `wifi`, `espnow`, `heartbeat`, `findme`, `time_heartbeat`, `stream_queue` and `power_transition`. Stopping these would leave the device unreachable or its power unsupervised.
  - `scan_stream` can be stopped, but its rate belongs to `set_scan_timing` and cannot be changed here (`period_fixed`).
- **Services**: `service_stop` / `service_start`, for `scanner` and `imu` only.
  - A stopped service gets no health checks or automatic retries, and resuming from soft-off, leaving maintenance mode or changing the matrix layout no longer brings it back behind your back.
  - Stopping `imu` does not change the `set_imu` setting; saving "on" with `set_imu` counts as an explicit start.
- **Apps**: `app_stop` / `app_start`, an "end task" that is not saved (`app_disable` remains the saved switch).

## Monitoring

- **`thread_list`**: FreeRTOS threads (loopTask, WiFi, esp_timer, IDLE, ...) with state, priority, stack low-water, CPU share and per-core load. Read-only; threads cannot be stopped. The first call has nothing to compare with, so CPU reads null.
- **`sysmon`**: tasks, services, apps, memory, scan, threads and airtime in one reply. Through a Hub (ESP-NOW carries one command per device at a time) the monitor now needs one command per second instead of five. Replies larger than one frame page through `result_page` as before.
- `task_list` gains `state`, `protected`, `fixed_period` and `default_period_us`; `service_list` gains `stoppable` and `operator_stopped`; `app_list` gains `governor` (the app budget governor). Apps have a new `stopped` state.

## App packages

- Recognises the new package kind **panel** (a readout that can act, drawn by the Desktop). Like a readout it is only stored in the registry and never runs on the device.
- The package size limit rises from 4096 to 8192 bytes (the system monitor panel is about 5.4 KB). The extra ~16 KB of heap is used only briefly while installing or activating, never held.

## Compatibility

- Pairs with the Desktop v1.3.0 system monitor; older Desktops keep working with existing features.
- Every new command is in the `commands` catalog, and the Desktop hides actions an older firmware lacks.
- Not yet verified on hardware: the actual size and page count of `sysmon` replies over ESP-NOW.
