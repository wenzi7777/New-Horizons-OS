# v2.3.1

**Devices in WiFi mode have about 44 KB more free memory (heap), and the largest free block roughly doubles.**

## Memory

- The ESP-NOW (New Horizons Direct) buffers for pairing, streaming, OTA relay and radio scheduling, about 44 KB in all, used to be reserved whatever the transport. They are now allocated only when the device boots in ESP-NOW mode; a WiFi / UDP device keeps that memory as heap.
- Measured on v2.0.F (WiFi, 14×10, no apps, 10 minutes each): median free heap 105.0 → 159.8 KB, largest free block 36.9 → 73.7 KB; scan fps and dropped frames unchanged.
- ESP-NOW mode uses the same total as before: the buffers moved from static memory to a boot-time heap allocation, and the heap itself grew by the same 44 KB, so `heap_free` in `memory_status` stays about the same while `heap_total` and `heap_used` each read about 44 KB higher.
- If the allocation fails when booting in ESP-NOW mode (out of memory; not expected in practice), the device boots in WiFi mode instead (saved WiFi if any, otherwise the setup portal) and logs `espnow_alloc_failed`.

## Compatibility

- In WiFi mode `airtime` in `status` / `sysmon` is `{}` and `airtime_arbiter` in the capability list is `false` (that scheduler serves ESP-NOW only).
- No protocol or command changes: works with current Desktop, NH Studio / Pocket / headless and Hub.
