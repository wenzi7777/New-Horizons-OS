# v1.7.2

**指令可以帶 `"quiet": true`，裝置就不做 LED 確認閃爍。** 輪詢和自動刷新不必再逐一寫進韌體的名單。

## 為什麼

v1.7.1 只讓 `app_view` 和 `app_events` 不閃燈，名單寫死在韌體裡。但會定時送指令的不只這兩個：
Readout 會輪詢 `status`、`sensor_sample` 等，設定頁也會自動刷新 `status` 和 `memory_status`。每一次都會閃約 660 ms，
而且閃爍優先於 app 的顏色。照這個做法，每多一個輪詢的指令就要發一次韌體。

## 變更

- 指令 payload 帶 `"quiet": true` 時，不觸發「收到」和「成功/失敗」閃爍。TCP、UDP、ESP-NOW 三條路徑都支援，
  任何指令都可以帶。
- v1.7.1 的名單（`app_view`、`app_events`）保留為預設，舊版 Desktop（v0.14.0）的輪詢一樣不會閃。
- 沒有帶 `quiet` 的指令照常閃燈確認。

## 驗證

- 5 塊板子的 release build 均通過；`tests/` 靜態測試全部通過。
- **本版尚未經過實機驗證**：開著 Readout 或設定頁的自動刷新時，LED 不應再持續閃爍；手動送出的指令仍要閃燈確認。

## 相容性

- 舊版韌體會忽略 `quiet` 欄位，照常閃燈，不會出錯。
- Desktop v0.14.1 起，所有背景輪詢與自動刷新都帶 `quiet`。
