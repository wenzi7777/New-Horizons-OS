# v1.8.0

**板子型號改名：VD-CTL/R → TIA-CTL/R。** 裝置回報的 `hardware_model` 現在是 `TIA-CTL/R …`。

## 為什麼

壓力矩陣的讀出電路是跨阻放大（TIA）：讀取線被運放固定在虛地電位，輸出和感測點的電導成正比。它不是分壓電路，所以產品名改成 TIA-CTL/R。PCB 不改名。

## 變更

- **回報的型號**：5 塊板子的 `NHOS_BOARD_NAME` 改成 TIA-CTL/R，例如 `TIA-CTL/R v1.5.F 2026.7`。status、FindMe、`/proc` 的 `hardware=` 都跟著改。
- **OTA 兩種名稱都接受**：`BoardConfig.h` 為每塊板子新增 `NHOS_BOARD_OTA_MODEL`，內容是改名前的 `VD-CTL/R …`。`OtaManager`（WiFi OTA）和 `EspNowOtaReceiver`（經 Hub 的 ESP-NOW OTA）比對 manifest 的 `model` 時，TIA 和 VD 兩個名稱都接受。
- **manifest 的 `model` 繼續寫 VD-CTL/R**：舊韌體只接受和自己名稱完全相同的 manifest。manifest 維持舊名，現場的 v1.7.5 以前版本就能直接 OTA 到這版，不需要 USB 重燒。build 腳本的 `--model` 因此不變。
- Windows 燒錄腳本顯示的板名和 README 改成 TIA-CTL/R。

## 驗證

- 5 塊板子的 release build 均通過；每個 binary 同時帶有 TIA 與 VD 兩個名稱。`tests/` 靜態測試全部通過（新增 OTA 接受舊名稱的檢查）。
- **本版尚未經過實機驗證**：
  - 一塊 v1.7.5 的板子 OTA 到 v1.8.0 應該成功，之後 Desktop 應顯示 `TIA-CTL/R …`。
  - v1.8.0 再 OTA 一次也不應出現 `model_mismatch`。

## 相容性

- **Desktop 要先更新到 v0.15.0**。較舊的 Desktop 認不出 `TIA-CTL/R …`，會把這塊板子當成 v1.0.F 預設設定。
- 指令與回應格式不變。
