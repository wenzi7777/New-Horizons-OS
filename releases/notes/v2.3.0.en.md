# v2.3.0

**A device's attachment to its relay is now a lease it renews: the device keeps checking that its relay is still there, and when the relay closes, changes IP or is taken over, it finds a new one within about 15 s. Pressing "Discover devices" is no longer needed.**

## FindMe lease

- **Searching** (just booted, relay lost, or a transfer running): as before, `findme_discover` is broadcast every 3 s and sent unicast to the last relay.
- **Attached**: every 5 s a discover goes unicast to the relay the device streams to (with `current_gateway_id` / `current_priority`); the relay's offer renews the lease. Every 3rd renewal is also broadcast as a beacon, so the relay that owns the device hears where it is; other relays stay silent. `findme.state` stays `attached` while renewing.
- **Lost**: after 3 renewals in a row without an answer (15–20 s after the relay stopped answering) the device searches and chooses a relay again. It keeps streaming to the old address until it takes a new offer, and stays if the old relay answers again. Earlier firmware stopped sending discovers once attached, so after the relay closed it kept sending data to the old address.
- During `findme_switch_gateway` (a takeover) discovers also go unicast to the address the command came from, so a takeover works on networks that drop broadcast. When it times out (30 s by default) the lease with the previous relay resumes.
- `findme_probe` answers are now throttled per asking address (once per 5 s each, up to 4 addresses), so relays probing at the same time no longer swallow each other's answers.

## Compatibility

- Message formats and priority rules are unchanged: old and new firmware, NH Studio / Pocket / headless and Desktop work together. It works best with NH Studio v2.11.0 (added devices are listed and found again without discovering).
