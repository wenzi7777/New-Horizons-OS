# v1.5.1

**只歸零（tare）就能生效**，而且不用進維護模式；重新歸零也不會再弄偏既有的壓力校準。

## 為什麼

過去只做 tare、不做壓力校準時，基線雖然會存進 flash，但串流完全沒有套用，輸出仍是原始值。
另外，壓力點是以絕對原始值儲存的，所以基線漂移後重新 tare，整條壓力曲線會跟著偏掉。

## 變更

- **只 tare 也會套用**：`calibration_tare_capture` 之後輸出改為 `max(0, raw − 基線)`，單位仍是 mV。
  有完整壓力校準並啟用時，照舊輸出 kPa。
  - 新增 `calibration_tare_clear`：停止套用單獨的 tare，基線本身保留。
  - 預設不套用，所以升級後既有裝置的輸出不會改變，要按一次歸零才會生效。
- **歸零不需要維護模式**：一般模式下會先暫停掃描、擷取約 1 秒後恢復，串流不會中斷。
  校準 session 進行中會回傳 `calibration_session_active`（session 中請用草稿基線
  `calibration_capture_tare`，否則 commit 時會被蓋回去）。
- **壓力點改為相對基線儲存**：每個壓力點存成「擷取值 − 當時的草稿基線」。重新歸零只會移動零點，
  kPa 換算不受影響。
  - 因此擷取壓力點前必須先有草稿基線，否則回傳 `calibration_tare_required`。
  - **舊資料自動轉換**：開機時用已存的基線把舊壓力點換算成相對值並寫回（`/cal/meta` 新增
    `levels_relative=1`）。沒有基線的舊 profile（`legacy_missing_tare`）維持原狀，歸零一次後即可使用。
- **重複 `calibration_session_begin` 不再清掉草稿**：session 已開啟時回傳
  `calibration_session_already_active`，已擷取的資料保留。網路重送不會再丟失進度。
- **status 新增欄位**：`calibration.tare_enabled`，以及 `calibration.output_mode`
  （`raw` / `tared` / `calibrated`）。
- **壓力曲線的計算集中到新的 `CalibrationCurve.cpp`**：不依賴 Arduino，並新增 native 測試
  `tests_native/test_calibration_curve.cpp`，驗證曲線、只 tare 的輸出、重新歸零後 kPa 不變，以及舊資料轉換。
- **編譯時必須指定板型**：沒帶 `-DNHOS_BOARD_*`，或帶了兩個，都會直接編譯失敗，不會再悄悄編成
  v1.0.F（曾經發生把 v1.0.F 韌體刷進 v2.1 GCU LTS）。每個 `flash_arduino_firmware*.sh` 都新增了
  Windows 用的 `.ps1` 版本。

## 驗證

- 5 塊板子的 release build 均通過；`tests/` 靜態測試與 `tests_native/` 全部通過。
- **本版尚未經過實機驗證**：一般模式歸零、重新歸零後 kPa 讀數，以及舊校準資料的轉換，
  都需要在實機上確認。

## 相容性

- Desktop v0.12.1 起的校準頁會使用上述新行為；搭配舊韌體時，歸零會自動改走維護模式。
- 使用 `calibration_capture_cell` / `calibration_capture_all` 的外部腳本，需要在同一個 session
  中先擷取基線。
