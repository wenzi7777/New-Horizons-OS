# v1.4.1

降低 `led` 與 `display` 兩個 task 的 CPU 佔用，並縮短 OLED 刷新時卡住 loop 的時間。

## 為什麼

在 System Monitor 上，`led` 約佔 20%、`display` 約佔 8–9%，比實際讀取感測器的 `imu`（約 15%）還高。

`loop()` 不會休息，一秒會跑上萬輪，而這兩個 task 都沒有設定週期，每一輪都會被呼叫。所以就算每次只花一點時間，累積起來也很可觀：

- **`led`**：外接燈條每次被呼叫都會完整送出一次像素，即使顏色完全沒變。v1.5.F 的 9 顆 WS2812 每次要編碼 216 個 RMT symbol 並等傳輸完成（約 270 µs）。另外每一輪都會查詢 heap 的最大可用區塊，並重新配置一次 preset 名稱字串。
- **`display`**：每一輪都先組好 IP、Gateway 等字串，才判斷還沒到刷新時間。OLED 關閉時也一樣在做這件事。

## 變更

- **`led` task 改為 100 Hz**，不再每一輪 loop 都執行。目前沒有任何 LED 動畫的變化快於 10 ms。
- **外接燈條只在畫面改變時送出**，每秒仍會強制重送一次，避免燈條受到干擾或掉電後一直顯示錯誤；從休眠喚醒時也會重送。
- **目前的 preset 名稱不再配置 heap**：原本是 `String`，每一輪都會配置一次，現在改成字面常數。
- **`display` 在不需要刷新時直接返回**：新增 `refreshDue()`，到了刷新時間才去組字串。
- **OLED 只送出有變化的列，並且分批送出**：原本每次刷新都送完整的 512 bytes，在 400 kHz 下約需 13 ms，loop 在這段期間完全停住，比一個 scan 週期還長。現在只送內容有變的 page（每個 page 就是一行文字），每一輪 loop 最多送一個 page（約 3 ms）。

## 注意

- loop 本來就在空轉，省下來的時間主要會變成更多次 `yield()` 讓給 WiFi，以及更準時的 scan。`busy_permille` 的總數不一定會跟著下降；應該觀察的是 `led`、`display` 各自的 `cpu_permille` 與 `max_us`，以及 OLED 開啟時的 `overrun_frames`。
- 全域變數約增加 520 B，主要是 OLED 的 512 B 比對緩衝。
