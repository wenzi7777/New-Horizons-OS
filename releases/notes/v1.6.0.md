# v1.6.0

**App 能讀 IMU、磁力計、電量與連線狀態**，能計時、能在任何尺寸的矩陣上用同一組區域，
還能在不串流時繼續執行、計數器重開機後也還在。App Library 同步新增 16 個 app。

## 為什麼

之前的 flow app 只看得到壓力矩陣與按鈕，時間窗最多 128 幀（約 2 秒），區域只能用絕對的列/行索引，
而且沒有 frame 就不會執行。步數、步頻、久壓提醒、跌倒偵測這類最常見的需求都寫不出來，
為 15×15 墊子寫的 app 放到 5×7 感測器上也會失效。

## 變更

- **新的 flow op**（App Library 會自動推導 `min_os: v1.6.0`）：
  - 時間與邏輯：`not`、`duration`（持續 ms）、`interval`（兩次上升沿間隔 ms）、`peak_since`、
    `counter_reset`（可歸零的計數器）、`sqrt`、`atan2`。都不佔時間窗，沒有 128 幀上限。
  - 區域掃描：`region_peak`、`region_active`、`region_row_centroid`、`region_col_centroid`。
  - 感測器：`imu`（ax/ay/az、gx/gy/gz、acc_mag、gyro_mag、pitch、roll）、`mag`（mx/my/mz、
    strength、heading）、`battery`（電量 %，沒有電量計時為 -1）、`linked`、`uptime`。
    讀的是隨該 frame 串流的樣本，所以與錄製檔一致；沒有樣本時保持上一個值。
- **百分比區域**：區域節點的 `rel` 欄位表示列/行是百分比，依每個 frame 實際的矩陣尺寸換算。
- **`emit_value` 的 `fall` 欄位**：在下降沿觸發（例如一步結束時回報該步峰值）。
- **背景執行**：宣告 `tick` 能力的 app，在 250 ms 沒有 frame 時改由 10 Hz tick 驅動；
  矩陣讀值保持最後的值，IMU/磁力計/電量讀最新樣本。有 frame 時不會重複執行。
- **計數器保存（`persist`）**：標記的計數器存進 NVS，重開機後還原。只在 app 時間預算之外寫入，
  最多每 30 秒一次，停用套件時也會寫；新版本套件或解除安裝後從 0 開始。
- **新能力**：`read_mag`（1<<12）、`persist`（1<<13），並開放 `power`、`link` 給 flow slot。
  未宣告的 app 拿不到磁力計樣本、電量（-1）與連線狀態（false）。
- **新唯讀指令 `sensor_sample`**：回傳最新的 IMU、磁力計與電量讀值，供 readout 圖表使用。
- **新檔 `FlowMath.cpp`**：區域換算與角度計算，不依賴 Arduino；App Library 的契約測試會直接編譯它，
  與模擬器逐值比對。

## 驗證

- 5 塊板子的 release build 均通過；`tests/` 靜態測試、App Library SDK 測試（含 `FlowMath.cpp` 對照）全部通過。
- v1.5.F 相對 v1.5.1：程式 +8 KB、全域 RAM +592 B。
- **本版尚未經過實機驗證**：計數器重開機還原、背景 tick 執行，以及 Hub 模式下的 `sensor_sample`，
  都需要在實機上確認。

## 相容性

- 既有 app 行為不變。App Library 的 `balance`、`heel_strike` 1.1.0 改用百分比區域（在 15×15 上與 1.0.0
  完全相同），因此需要 v1.6.0。
- Desktop v0.13.0 起支援 readout 圖表與 `sensor_sample`。
