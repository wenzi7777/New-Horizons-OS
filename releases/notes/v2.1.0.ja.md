# v2.1.0

**アプリを命令型プログラム（TypeScript 風）で書けるようになり、システムコールを追加しました：ストレージ、アプリ間メッセージ、デバイス設定とストリーミング、v1.5.F / v2.0.F の外部 I2C / UART。危険な権限はインストール時にオペレーターの同意が必要です。**

## アプリのシステムコール

- **ストレージ**（`storage`）：アプリごとに最大 16 個の数値（`store.get` / `store.set`、NVS に保存、書き込みは最大 30 秒に 1 回と停止時）と CSV ファイル（`store.append`、appdata スコープの `<id>/<ファイル名>.csv`）。アプリのファイルは合計 16 KB まで。超える行は拒否され、`store_full` イベントが 1 回だけ発行されます（アプリは停止しません）。行はアプリごとの固定 256 B バッファを通り、満杯時または 10 秒ごとに flash へ書き込まれます。
- **アプリ間メッセージ**（`app_ipc`）：`app.publish(topic, 値)` は `on("message", topic, …)` で購読している他のアプリに届きます。キューはアプリごとに 4 件、あふれた分は `events_dropped` に数えます。
- **デバイス設定**（`device_config`）：実行中のアプリは `scan.target_fps`、`scan.send_every_n_frames`、`filter.enabled/median/alpha`、`imu.enabled` を通常と同じ範囲で、1 秒に 1 回まで変更できます。**NVS には保存されず**、アプリの停止・エラー・削除で元の値に戻ります。
- **ストリーミング**（`device_stream`）：`device.stream(false/true)` で relay へのストリームを一時停止 / 再開。アプリが停止すると自動的に再開します。
- **外部 I2C**（`io_i2c`、v1.5.F / v2.0.F のみ）：7 ビットアドレス。ボード上のチップ（0x14、0x36、0x3C/0x3D、0x41、0x60、0x68、0x6A）は常に拒否。1 回 32 B まで、タイムアウト 5 ms、NACK はアプリを止めずに -1 を返し、転送時間はそのアプリのタイムスライスに含まれます。
- **外部 UART**（`io_uart`、v1.5.F / v2.0.F のみ）：FPC1.17 TX / FPC1.16 RX、1200–921600 baud。ドライバーと 256 B の受信バッファは開いている間だけ存在し、アプリ停止時に閉じてピンを入力に戻します。
- 配列引数はシステムコール内で範囲を検査し、範囲外は `bad_syscall_arg` エラーになります。実行中のヒープ確保は引き続きありません。

## アプリ：固定数をなくし、リソースプールを共有

- 4 つの固定スロットを廃止しました。アプリは 8 KB のメモリプールとフレームごとの時間予算を共有し、収まるだけ同時に動きます。重いアプリ 1 つでほぼ全部を使うことも、軽いアプリを多数動かすこともできます。プールが足りなければ `app_pool_exhausted`、ループのないアプリの推定時間が予算を超えれば `app_budget_exhausted` を返します。インストールできるパッケージは最大 16 個（インデックスの上限。実際には flash が上限）。
- アプリをオン（`app_activate`）にすると、すぐに、そして起動のたびに実行されます。`app_deactivate` で停止してメモリを解放します。アプリはどこでも ID で呼ばれます（`app_list`、`app_view`、`app_events`、`/proc/apps`、イベント CSV）。`flow1` のような名前はなくなりました。`slot` 引数は受け付けますが無視します。
- アプリに必要なメモリはビルド時に決まり、起動時にまとめて確保するため、実行中にメモリ不足になることはありません。ストレージ用バッファは `storage` 権限を持つアプリにだけ確保します。
- 実行中のアプリは負荷を報告します：1 秒 / 10 秒 / 60 秒の CPU と、0–100 の `load` とレベル（`low` / `medium` / `high` / `overloaded`）。`app_list`、`app_view`、`/proc/apps` に含まれます。
- 時間は公平に分け、1 アプリあたり予算の半分まで（1 つだけのときは全部）。`burst: true` でビルドしたアプリは、他のアプリが使っていない時間を借りられます。毎秒再計算し、他のアプリが必要になればすぐ返します（保証はありません）。`app_list` は `base_us`、`borrowed_us`、`lent_us` を報告します。
- 新コマンド `app_reorder`（`id`、`to`）：前にあるアプリが共有の OLED 行とステータス LED を優先します。
- 削除：`app_enable` / `app_disable`（`app_activate` / `app_deactivate`、または再起動までの一時停止は `app_stop` / `app_start`）と、旧デバッグ用の `app_load_flow` / `app_unload_flow` / `apps/flow.json`。
- v2.0.x のインデックスは移行されます：スロットにあったアプリはスロット順でオンのままです。
- 静的 RAM は v2.0.0 より約 5 KB 増えました（4 KB のプールと 4 つのアプリオブジェクトを 8 KB のプールに置き換え、パッケージインデックスを 8 件から 16 件に拡張）。空きヒープは約 6 KB 減ります（v2.0.F でアプリ 4 つのとき 110 KB）。

## 権限と同意

- 権限ビットを 32 ビットに拡張し、`storage`、`app_ipc`、`device_config`、`device_stream`、`io_i2c`、`io_uart` を追加しました。
- `app_install` に新しい引数 `grant`（文字列の配列）。危険な権限（storage、device_config、device_stream、io_i2c、io_uart）を宣言しているのに許可されていないパッケージは拒否されます（`capability_not_granted:<権限>`）。ボードにない I/O を求めるものも拒否されます（`capability_unsupported:<権限>`）。許可はパッケージ索引に保存され、`app_list_packages` が `granted` として返します。
- アプリを削除すると、その数値と appdata ファイルも削除されます。

## 互換性

- App Library 3.0.0 のアプリは TypeScript 風のソースからコンパイルされ、v2.1.0 ファームウェアが必要です。2.0.0 のアプリは v2.1.0 でもそのまま動きます。
- 3.0.0 のアプリのインストールには New Horizons Desktop v1.12.0 / NH Studio v2.8.0 以降が必要です（旧版は `nodes` のないパッケージを検証できず、`grant` も送りません）。
