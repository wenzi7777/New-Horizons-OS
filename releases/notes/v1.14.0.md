# v1.14.0

**更新通道（正式版／測試版）、OTA 驗證伺服器憑證、Desktop 讀狀態不再卡住掃描，並修正電池設定重開機就消失。**

## 更新通道

- 每台裝置可以選 `stable`（正式版，預設）或 `beta`（測試版）。設定方式：`set_ota_config` 的 `channel`、config 鍵 `ota.channel`，或 Desktop 的更新設定。
- stable 讀 `*-latest.json`，beta 讀 `*-beta.json`。beta 也會收到每個正式版。
- 測試版的版號是 `vX.Y.Z-beta.N`，排在對應正式版之前（`v1.15.0-beta.1 < v1.15.0`）。以前的版本比較會把 beta 當成正式版，正式版就推不到 beta 裝置；這版已修正。
- 從 beta 切回 stable 不會降級：裝置會留在目前的 beta，等正式版的版號超過它再自動更新。
- `ota.manifest_url` 改成「自訂網址」，留空就跟隨通道。以前存著的預設網址開機時會自動轉成留空。
- `status` 新增 `firmware_prerelease`，`ota` 區塊新增 `channel`、`resolved_manifest_url`；`capabilities.features` 新增 `ota_channels`。
- App 的 `min_os` 只比較主版號，所以測試版也能安裝要求對應正式版的 App。

## OTA 安全性

- 下載 manifest 與韌體時改為驗證 HTTPS 憑證（內建 Mozilla 根憑證），不再接受任何人。不檢查到期日，時鐘還沒同步的裝置一樣能更新。
- 使用自簽憑證的自訂 manifest 伺服器會無法連線。
- `app_install` 必須帶 `sha256`，否則回 `sha256_required`（Desktop 一直都會帶）。

## 掃描不再被 Desktop 的查詢卡住

- 超過一個 datagram 的 UDP 回覆，以前會在主迴圈一次送完、每塊之間 `delay(3)`：一次 `status` 卡住掃描約 116 ms（60 fps 少 7 個 frame）。現在每個迴圈只送一塊，而且只在兩次掃描之間的空檔送；格式不變，只是分散在幾個 frame 內送完。v1.5.F 實測：`status` 116 → 約 8 ms，`task_list` 32 → 約 1 ms。
- `status` 讀 log 檔大小不再開檔（改用快取）。
- `storage_status` 只走訪檔案系統一次（以前每個分類各掃一次）：v1.5.F 上 530 → 約 90 ms。
- 新增唯讀指令 `battery_status`：只回 `battery`、`battery_gauge`、`power`（約 1.9 KB，組裝約 2 ms，`status` 約 18 KB、14 ms）。Desktop 在電池計重新同步時改輪詢它。

## 新的量測：掃描開始延遲

- `scan_health`（以及 `status`、`/proc/scan`）新增 `start_lateness`：每次掃描比預定時間晚了多少，分成 <0.5／<2／<5／≥5 ms 四格，另有最大值、最近 5 秒最大值，以及 ≥250 ms 的暫停次數。
- 以前的 `overrun_frames` 只計算掃描本身超時，看不到「主迴圈被別的事情卡住而晚開始」，這項指標補上了這個盲點。

## 修正

- **手動電池設定重開機就消失**：NVS 鍵名超過 15 字元上限，寫入一直失敗。改用 `bat_cap_mah`、`bat_max_chg_ma`。v1.14.0 起設定一次就會保留（以前其實從沒存成功，所以升級後要再設一次）。
- **「只有第一次開機才格式化 SPIFFS」的保護從沒生效**：同樣是鍵名太長（`spiffs_initialized`）。改用 `spiffs_init`，以後掛載失敗會回報 `mount_failed`，不會再把校正與 App 格式化掉。
- 移除靜態串流目的地：以前 FindMe 找不到 Gateway 時，會退回 NVS 裡舊的 `stream_host`，但這個值早已沒有指令能設定（第二個 `set_transport` 分支永遠執行不到）。現在只送到 FindMe 找到的 Gateway。

## 建置

- 所有板子的 board define 都改走 `compiler.cpp.extra_flags`。GCU 板以前覆寫 `build.extra_flags`，會丟掉 core 的預設 define；這版起 GCU 韌體不再在序列埠印 core 自己的 `[E]` 錯誤訊息，大小因此約減少 50 KB（憑證驗證則增加約 70 KB）。
- 發布腳本支援 `CHANNEL=beta`，並拒絕把測試版寫進 `-latest.json`。

## 相容性

- 搭配 Desktop v0.22.0 才有通道切換與延遲欄位的 UI；舊版 Desktop 仍可正常使用。
- 經 Hub 連線的裝置，OTA 由 Hub 代抓 manifest：Hub v0.9.0 起也會驗證憑證。
