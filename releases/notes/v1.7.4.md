# v1.7.4

**修正：`dmesg` 幾乎沒有內容。** RAM 裡的 log ring 不再被 flash log 的全域等級過濾。

## 為什麼

調查 AC14 的開機問題時，`dmesg` 只回了一行 `boot_stage=storage_ready`，flash log 也只有這一行，每次開機重複一次。

- flash log 的全域等級出廠預設是 `error`，但韌體裡所有的開機、OTA 紀錄都是 Info，所以都不會寫進 flash。
  這是為了減少 flash 磨損，照設定運作。
- RAM ring 的本意是：就算 flash log 關閉或調低，也照樣記錄，而且它不耗 flash。但等級過濾發生在寫入 ring **之前**，
  所以 flash 的等級設定把 ring 也一起過濾了。這是 bug。
- 唯一留下的 `storage_ready`，是因為它在設定載入之前寫入，那時等級還是預設的 Info。

crash 紀錄（`crash_log`）用的是 reset reason 和獨立的 core dump 分區，不經過 log 系統，所以不受影響。

## 變更

- **RAM ring 一律記錄 Info 以上**，不受全域等級影響。全域等級只決定寫不寫 flash。
  - 替某個 tag 單獨設的等級，仍然同時套用在 ring 和 flash，想讓特定子系統安靜下來時可以用。
  - 執行期幾乎沒有 Info 等級的 log，所以 24 格的 ring 不會被洗掉，開機後 `dmesg` 會保留最後 24 行開機紀錄。
- **回報的等級名稱就是實際生效的等級**：空字串現在是真正的 `error`（之前顯示 `error`、實際按 Info 過濾），
  無法辨識的值會顯示成實際生效的 `info`，不再原樣回報。
- flash log 的行為不變。

## 驗證

- 5 塊板子的 release build 均通過；`tests/` 靜態測試全部通過（新增 2 個檢查）。
- **本版尚未經過實機驗證**：開機後 `dmesg` 應該能看到開機階段的紀錄。

## 相容性

- 指令與回應格式不變。Desktop 不需要更新（v0.14.1 即可）。
